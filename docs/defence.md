# Як пояснити StudyHub на захисті

## Вступ на 1 хвилину

Я розробив освітній портал StudyHub для студентів, які вивчають веброзробку. Обрав другий варіант — Decoupled CMS. WordPress використовується для створення та зберігання матеріалів, а Next.js — для окремого інтерфейсу сайту. Вони обмінюються даними через REST API. На порталі працюють пошук, категорії, пагінація, обкладинки, українська й англійська версії. Автор подає матеріал на перевірку, редактор публікує його. CMS розгорнуто на alwaysdata, фронтенд — на Vercel.

## Що означає кожна частина

- **WordPress — кабінет для контенту.** Тут додають текст, фото, категорії, переклади й користувачів.
- **MariaDB — база даних.** Зберігає записи, користувачів і зв’язки між сутностями. Фронтенд до неї напряму не підключається.
- **REST API — спосіб отримання даних.** Next.js звертається до адреси `/wp-json/wp/v2/posts`; WordPress повертає JSON зі статтями.
- **Next.js / React — сайт для відвідувача.** Перетворює дані на сторінки, картки й навігацію.
- **TypeScript — перевірка типів у коді.** Допомагає виявити помилки в структурі даних до запуску.
- **Docker — локальне середовище.** Запускає WordPress і базу в контейнерах на комп’ютері.
- **Polylang — зв’язки мовних версій.** Українська й англійська статті — окремі записи, пов’язані як переклади.
- **MU-плагін — власне розширення WordPress.** Додає мовні поля до REST API і фільтрацію за мовою. Завантажується автоматично.
- **Vercel і alwaysdata — два хостинги.** Перший запускає Next.js, другий — PHP WordPress і MariaDB.

## Який файл за що відповідає

| Файл | Призначення |
|---|---|
| `app/page.tsx` | Головна, каталог, пошук, категорії, пагінація |
| `app/materialy/[slug]/page.tsx` | Окрема стаття за її адресою |
| `app/lib/wordpress.ts` | Отримання даних і очищення HTML |
| `app/lib/i18n.ts` | Переклади написів інтерфейсу |
| `app/components/site-chrome.tsx` | Шапка й підвал, що реагують на зміну мови |
| `app/lib/seo.ts` | Canonical, мовні посилання, метадані |
| `app/sitemap.ts`, `app/robots.ts` | Службові дані для пошуковиків |
| `wordpress/mu-plugins/studyhub-language.php` | Мовні поля й мовна фільтрація REST API |
| `compose.yaml` або файл Compose в репозиторії | Налаштування локальних контейнерів |

## Покажи сайт у такому порядку — 3–5 хвилин

1. Відкрий https://web-independent-work.vercel.app/ і поясни тему порталу.
2. Перейди до матеріалів, обери категорію й виконай пошук. Введи також слово, якого немає, щоб показати порожній результат.
3. Відкрий статтю: заголовок, автор, текст, обкладинка.
4. Перемкни EN, відкрий англійську статтю або її переклад.
5. У WordPress покажи список матеріалів і користувачів Contributor / Editor. Поясни чернетку → перевірку → публікацію.
6. Покажи `/robots.txt` і `/sitemap.xml`, а потім репозиторій GitHub.

## Поширені запитання

**Чому дві адреси?** Фронтенд і CMS — окремі застосунки. На Vercel користувач читає, на alwaysdata редактор керує матеріалами.

**Що таке slug?** Частина адреси статті, наприклад `html-en`. Українські символи можуть бути представлені процентним кодуванням у URL.

**Чому зміна статті не завжди одразу з’являється?** REST-запити кешуються на 60 секунд. Наступні запити оновлюють дані за правилами кешування Next.js; миттєвого webhook немає.

**Як захищено від XSS?** HTML із CMS очищується бібліотекою sanitize-html за списком дозволених тегів. Не допускаються script, обробники подій і небезпечні URL.

**А SQL Injection?** Фронтенд не складає SQL і не має облікових даних бази. Параметри отримує стандартний REST API WordPress. Повний аудит WordPress не проводився.

**Як захищено редагування?** WordPress перевіряє автентифікацію й права. Contributor не може самостійно опублікувати статтю, Editor може.

**Що зроблено для SEO?** Title, description, canonical, hreflang, Open Graph, sitemap і robots. Налаштування не гарантують індексацію Google.

**Що перевірено?** Збірку, типи й локальні smoke-тести; публічні кнопки перевірено вручну. Мобільну головну перевірено на телефоні, повний набір браузерів не тестувався.

**Що покращити далі?** Webhook для оновлення кешу, моніторинг, регулярні резервні копії, більше мобільних тестів і навчального контенту.

## Перед здачею

Відкрий Word-звіт і PDF, перевір ім’я та групу. Переглянь слайди. Після автоматичного розгортання останнього виправлення перевір відкриття української статті та sitemap. Не прикладай паролі, `.env` або архів Duplicator до звіту чи GitHub. Підготуй посилання на сайт і репозиторій.
