# Перевірка першого етапу — 2026-10-06

- `npm ci --cache /workspace/.npm-cache`: встановлення з lockfile успішне.
- `npm run build`: production-збірка успішна.
- `npm run typecheck`: TypeScript без помилок.
- `npm audit --omit=dev`: відомих вразливостей у production-залежностях не виявлено на момент перевірки.
- `npm run smoke`: 6 функціональних перевірок пройдено з реальною WordPress CMS.
- Повторний `npm run cms:seed` не створив дубль навчальної статті.

Smoke перевіряє існування початкової статті в API, посилання з головної, її текст на фронтенді, HTTP 404 невідомої статті, заборону читання чернеток і заборону анонімного створення матеріалів. WordPress повертає зовнішній HTTP 400 для недозволеного параметра `status=draft`, із вкладеним кодом `rest_forbidden_status`; перевірка перевіряє цей код, а не лише статус.

Не перевірено: візуальний вигляд реальним браузером, публічний деплой, повний цикл редакторського погодження та мультимовність. Це наступні етапи. Docker volumes зберігають дані у поточному середовищі; відновлення в новій cloud-сесії не підтверджене. Setup може відтворити початкову статтю, але не замінює резервну копію майбутнього контенту.

## Етап 2: категорії

Production-збірка та TypeScript успішні. Розширений `smoke` пройшов проти реального WordPress: матеріал своєї категорії показується, матеріали інших категорій виключаються, вибраний фільтр позначено активним, невідома категорія має зрозумілий порожній стан. Базові перевірки статті та захисту також пройшли. Візуальна перевірка браузером залишається невиконаною.

## Етап 3: пошук

Production-збірка успішна. Smoke проти реальної CMS перевірив пошук за текстом матеріалу разом із категорією, збереження параметрів та порожній результат для невідомого запиту. Попередні перевірки категорій і безпеки також пройшли.

## Етап 4: пагінація

Збірка, TypeScript та попередній smoke пройшли. Із двома тимчасовими статтями у хмарній CMS перевірено: 3 картки на першій сторінці, 1 на другій, відсутність повторів, переходи, повідомлення для сторінки 999 та нормалізацію -1 до першої сторінки. Тимчасові статті після перевірки видалено.

## Етап 5: обкладинки

Збірка успішна. Smoke із реальною тестовою обкладинкою перевірив зображення у статті та доступність URL. Додатково перевірено HTML картки, URL картинки та Alt Text із CMS. Тимчасове медіа й прив’язку після перевірки видалено. Візуальний вигляд і обробку помилки завантаження реальним браузером ще не перевірено.

## Етап 6: мультимовність

Збірка, TypeScript, PHP lint та базовий smoke пройшли. `smoke:languages` пройшов із реальним Polylang: мовна ізоляція API/каталогу, `html lang`, англійський інтерфейс, посилання на переклад, 404 для чужої мови, категорії та пошук. Додатково перевірено: неопублікований переклад не потрапляє в API-посилання, відсутній переклад пояснюється, невідома мова API повертає 400. Тестові англійські матеріали та категорію після перевірок видалено.

WordPress.org повернув 403 у хмарі. Для перевірки backend використано офіційний GitHub-тег Polylang 3.8.10 (8e2ab6f42680886c841663e8bbf697f5cfb5608f), PHP-autoloader створено Composer dump-autoload без зовнішніх PHP-залежностей. Адміністративний інтерфейс цього складання та вигляд Next.js реальним браузером не перевірені. На Mac використовується плагін, встановлений через WordPress.

## Виправлення шапки під час перемикання мов

Спільний root layout зберігається при переходах Next.js, тому серверне визначення мови не оновлювало шапку й підвал. Вони винесені в клієнтські компоненти, що читають usePathname; html lang синхронізується ефектом. Збірка, TypeScript і базовий smoke пройшли. Окремий DOM-тест у jsdom перевірив ті самі змонтовані компоненти без перемонтування: UA → EN → англійська стаття → UA, переклади шапки/підвалу, адреси навігації й html lang. Для цього тесту маршрут Next.js замінено керованим useSyncExternalStore. Повноцінний браузерний тест не виконано: завантаження Chromium відхилене мережевою політикою (403).

## Етап 7: SEO

Збірка й TypeScript пройшли. `smoke:seo` перевірив sitemap, включення всіх опублікованих матеріалів CMS, мовні alternates, robots, canonical, Open Graph, Twitter Card, noindex для пошуку та справжній PNG загальної обкладинки. Перевірки виконано для localhost і окремої збірки з умовною публічною адресою https://studyhub.example: для неї robots дозволяє індексацію, адреси в метаданих і sitemap використовують заданий домен. Це локальна перевірка конфігурації, не публічний деплой або перевірка індексації Google. Базовий smoke також пройшов.

## Фіналізація — 2026-10-07

Користувач підтвердив роботу публічної версії на Vercel, надав скріншоти robots, sitemap і мобільної головної. У sitemap виявлено подвійне кодування кириличного post_name WordPress. articlePath тепер декодує вхідний сегмент один раз перед encodeURIComponent; той самий helper використано для карток і посилань перекладів. Перевірено український Unicode slug, уже закодований slug, англійський slug і буквальний %. TypeScript та production build успішні. Публічна перевірка після цього оновлення користувачем ще потрібна.

Звіт і презентацію підготовлено з наданих скріншотів та кафедральних стилів. Мобільний скріншот у повідомленні розглянуто, але він не входить до архіву зображень; у звіті зазначено межі перевірки.
