# Етап 1. Від WordPress до сторінки

## Що відбувається

1. У WordPress автор заповнює заголовок і текст, натискає «Опублікувати».
2. CMS записує матеріал у MariaDB.
3. Next.js на сервері запитує `/wp-json/wp/v2/posts`.
4. WordPress відповідає JSON-масивом. `title.rendered` містить заголовок, `content.rendered` — HTML тексту, `slug` — частину адреси.
5. React-компонент створює сторінку. Браузер не підключається до бази даних і не отримує пароль CMS.

## Прочитай код у цьому порядку

`app/lib/wordpress.ts` → `app/page.tsx` → `app/materialy/[slug]/page.tsx` → `app/globals.css`.

`async/await` дозволяє дочекатися HTTP-відповіді. `Post` описує очікувану структуру даних для TypeScript; цей тип не замінює перевірку JSON під час виконання. `map` перетворює масив статей на картки. `params` містить адресу потрібного матеріалу. `notFound()` повертає сторінку 404, якщо матеріалу немає.

CMS повертає HTML. `dangerouslySetInnerHTML` вставляє його як розмітку, тому перед вставленням обов’язково викликаємо `safeContent`. Він дозволяє лише визначені теги й атрибути, прибирає scripts і обробники подій. Кешування `revalidate: 60` означає, що запит може використати попередні дані. Оновлення після завершення інтервалу може відбутися у фоні: іноді потрібно ще одне відкриття сторінки.

## Твоя практика

1. Зміни останній абзац навчального матеріалу через WordPress. Дочекайся оновлення кешу й знайди зміну на сайті.
2. Відкрий API у браузері на своєму комп’ютері. Знайди `id`, `slug`, `title`, `content`.
3. Зміни текст кнопки головної сторінки у `app/page.tsx`.
4. Зміни колір `--green` у CSS. Поясни, які елементи змінилися.
5. Створи другу статтю через CMS: картка має з’явитися без зміни фронтенду.

## Питання для захисту

- Чому це decoupled CMS?
- Де зберігається контент, а де описаний вигляд сторінки?
- Чим REST API відрізняється від бази даних?
- Навіщо очищувати HTML?
- Чому зміни не завжди з’являються миттєво?

Відповідай власними словами й показуй відповідний файл. Не потрібно заучувати весь код.

## Етап 2. Категорії

WordPress має власні ID категорій. Фронтенд завантажує непорожні категорії через `/categories`, читає `category` з URL, знаходить ID за slug і запитує `/posts?categories=ID`. Це фільтрація на CMS, а не приховування вже отриманих карток. `wp:term` в API-відповіді містить назви категорій матеріалу. Посилання «Усі» скидає фільтр; URL можна скопіювати й відкрити повторно. Категорії без опублікованих статей не показуються.

## Етап 3. Пошук

Форма надсилає GET-параметр `q`. Сервер обрізає пробіли й обмежує запит 200 символами, передає його до WordPress як `search`. Пошук WordPress охоплює заголовок, короткий опис і текст матеріалу. Категорія передається одночасно; при перемиканні категорії запит зберігається. «Очистити пошук» прибирає тільки запит. URLSearchParams правильно кодує символи, а React екранує введений текст у сторінці.

## Етап 4. Пагінація

Каталог запитує WordPress із `per_page=3` та `page`. Заголовки відповіді `X-WP-Total` і `X-WP-TotalPages` повідомляють кількість матеріалів та сторінок для поточного пошуку й категорії. Кнопки переходу зберігають ці фільтри. Новий пошук або категорія починаються з першої сторінки. Некоректний номер нормалізується до 1; номер поза межами каталогу показує повідомлення та посилання на першу сторінку.

## Етап 5. Обкладинки

WordPress повертає обкладинку через `_embed=wp:featuredmedia`. Фронтенд використовує `source_url` та `alt_text`, а за відсутності опису — назву статті. Компонент `CoverImage` показує обкладинку в каталозі та статті. Зображення завантажує браузер без серверної оптимізації Next.js: це підтримує локальний WordPress на Mac. Якщо файл недоступний, на картці залишається ілюстрація, а в статті зображення приховується. Перед деплоєм адреси медіа WordPress мають бути публічними HTTPS-адресами.

## Етап 6. Мультимовність

Polylang зберігає мову й зв’язки перекладів. Наш MU-модуль додає `lang` до REST-запитів і поля `studyhub_language`, `studyhub_translations`. У публічні посилання потрапляють лише опубліковані переклади. Next.js має українські маршрути `/` та `/materialy/...`, англійські `/en` та `/en/materialy/...`. Словник перекладає інтерфейс; тексти статей залишаються під контролем CMS. Proxy визначає мову маршруту для `html lang` і навігації.
