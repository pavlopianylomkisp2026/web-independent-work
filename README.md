# StudyHub

Освітній портал для самостійної роботи, варіант 2: **Decoupled CMS**.
WordPress керує контентом, а окремий Next.js-фронтенд отримує його через REST API.

## Перший етап

Реалізовано адаптивну головну сторінку, каталог опублікованих матеріалів із пагінацією по 3 на сторінку, сторінку матеріалу, метадані, обкладинки з Featured image WordPress, очищення HTML, кеш на 60 секунд, повідомлення про недоступність CMS і сторінку 404. Одна навчальна стаття створюється повторюваним seed-скриптом. Категорії на картках і в статтях надходять із WordPress; каталог фільтрується за категорією через URL. Показуються категорії з опублікованими матеріалами. Пошук через WordPress API працює разом із категоріями; запит зберігається в URL. Пагінація використовує кількість результатів із WordPress і зберігає пошук та категорію. Полілінгвальна версія доступна на `/en`: інтерфейс перекладено, контент фільтрується за мовою Polylang. Повний редакційний процес — наступні етапи, а не готові можливості.

## Локальний запуск

Потрібні Node.js 24, npm і Docker із Compose.

```sh
npm ci --cache /workspace/.npm-cache
npm run cms:start
# Дочекайся відповіді WordPress на порту 8080, тоді:
npm run cms:seed
npm run dev
```

На власному комп’ютері параметр `--cache /workspace/.npm-cache` можна опустити.
CMS працює на порту 8080, Next.js — на 3000. WordPress admin: `/wp-admin`, користувач `studyadmin`. Пароль згенеровано в локальному `.env` (`WP_ADMIN_PASSWORD`); відкрий цей файл локально, не публікуй і не копіюй його в звіт. `.env` не потрапляє в Git. Це конфігурація розробки, не production-деплой.

```sh
npm run build
npm run typecheck
# npm run start запускає перевірену production-збірку
npm run smoke
```

Smoke-перевірка потребує запущених CMS і фронтенду. Дані зберігаються в Docker volumes. `docker compose stop` зупиняє CMS без видалення даних. Не запускай `down -v`, якщо хочеш зберегти матеріали. Повторний seed не переписує наявну навчальну статтю.

## Де що знаходиться

- `app/page.tsx` — головна сторінка й картки матеріалів.
- `app/materialy/[slug]/page.tsx` — сторінка статті; `slug` береться з URL.
- `app/lib/wordpress.ts` — HTTP-запити до CMS та очищення HTML.
- `app/globals.css` — адаптивне оформлення.
- `compose.yaml` — WordPress, MariaDB і службовий WP-CLI.
- `scripts/seed.sh` — початковий контент.
- `docs/learning-01.md` — пояснення першого етапу та вправи.
- `docs/report.md` — початок звіту; незавершені розділи позначено.

## Обмеження

CMS використовує локальні HTTP-адреси. Перед публікацією потрібні окремий PHP/MySQL-хостинг, HTTPS, production-секрети, резервні копії та коректні публічні адреси. У cloud onboarding браузерні localhost-посилання не є доступним прев’ю. Не оприлюднюй адміністративну панель із цією локальною конфігурацією.

## Мультимовність (Polylang Free)

Встановіть і активуйте Polylang через WordPress → Plugins. Додайте `uk` та `en`, призначте українську мову всім наявним матеріалам і категоріям. Створюйте пов’язані переклади через «+» у мовній колонці; призначайте категорії відповідної мови.

Після оновлення коду виконайте `npm run cms:start`, щоб Compose підключив папку `wordpress/mu-plugins`. Модуль StudyHub Language API завантажується автоматично (WordPress → Plugins → Must-Use); активувати його кнопкою не потрібно. Docker volumes із вашим контентом залишаються на місці.

UA відкриває `/`, EN — `/en`. Перемикач у шапці веде до каталогу відповідної мови; посилання біля заголовка статті відкривають саме її пов’язаний переклад. Якщо його немає, відображається повідомлення. При зміні мови каталог починається без попередніх фільтрів. Усередині мови категорії, пошук та пагінація зберігають мовний маршрут.

`npm run smoke:languages` перевіряє мовну ізоляцію, англійський інтерфейс, пов’язані статті й пошук. Потрібні запущені CMS/фронтенд і щонайменше одна пара опублікованих перекладів. Команда нічого не створює і не змінює в CMS.

Без Polylang українська версія продовжує працювати, англійська не показує українські статті. Після встановлення Polylang матеріали без призначеної мови потрібно позначити в CMS. Для зовнішнього WordPress-хостингу файл `wordpress/mu-plugins/studyhub-language.php` необхідно розмістити у `wp-content/mu-plugins`.
